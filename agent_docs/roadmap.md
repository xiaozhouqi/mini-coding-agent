# Roadmap — 从 MVP 到完整 Coding Agent

> 长期产品规划文档。对照 Claude Code 的核心能力，梳理当前 MVP 的差距，并按**产品功能的用户价值**（而非技术难度）排序，给出分阶段扩展计划。
>
> 最后更新：2026-10-25。当前状态：v0.1 MVP 已交付（见 `MEMORY.md`）。

## 一、结论先行

当前 MVP 已经把"一个 agent 的最小子集"做对了：ReAct 循环、工具调用、进程隔离（stdio JSONL 子进程）、沙箱、写确认、会话持久化、密钥脱敏。这是**骨架**，架构方向正确——尤其 `LLMAdapter` 抽象、`ToolSandbox` 与 `desensitize` 的 deterministic 边界，和 Claude Code 的理念一致。

但它本质仍是一个**"能读/写文件 + 聊天的演示"**，不是"能真的干活"的 coding agent。与 Claude Code 最大的、唯一压倒性的差距是：**agent 不能执行代码**。其余差距大多是这一点的延伸。

一个横向的、不能靠"加功能"补上的因素：**模型能力**（见第四节）。它是每一层功能的天花板。

## 二、核心功能差距逐项分析

按"功能 → 差距 → 影响什么 → 用户价值"列出。

| # | 功能 | Claude Code 有 | 当前 MVP | 影响 | 用户价值 |
|---|------|----------------|----------|------|----------|
| 1 | 终端执行 | 运行任意 shell（测试/构建/git/装依赖/启动） | 无，bash 被明确列为 v0.2 | 无法运行测试/构建/启动，**无法验证自己的改动**；写代码是"盲写"，没有反馈闭环 | **最高（质变）** |
| 2 | 精确/增量编辑 + Diff | `Edit` 精确替换、多文件并行、diff 逐处确认、可回退 | 只有 `write_file` 整体覆盖 + 逐次确认 | 真实仓库改一行也要重写整个文件；无 diff 视图，难以审阅 | **很高** |
| 3 | Git 集成与安全默认 | 默认分支工作、按需 commit、diff、发 PR、worktree | 无 git 感知 | 无版本化"改了什么"，无法安全回退/产出可审查 PR | **高** |
| 4 | 上下文与记忆 | CLAUDE.md/AGENTS.md、长期记忆、1M 上下文 + 自动压缩、prompt caching | 仅会话内历史；无项目指令/长期记忆/压缩 | 跨会话丢约定；长任务失忆退化；无法沉淀项目知识 | **很高** |
| 5 | 规划模式 | 只读探索 → 方案 → 批准 → 再执行 | 无，直接进入执行 | 复杂任务直接动手，易走偏、浪费 token、缺信任 | **高** |
| 6 | 工具面 + MCP | WebFetch/WebSearch、Task、NotebookEdit；MCP client（stdio/SSE/HTTP/WS） | 仅 4 个文件工具；无网络；无 MCP | 无法查最新文档；无法对接外部系统；工具面不可扩展 | **中高** |
| 7 | 子代理 / 并行 / 后台 | 子代理独立上下文、Workflow 编排、后台长任务 | 单进程单循环、串行 | 无法并行扇出；主上下文易被污染 | **中高** |
| 8 | Hooks + 精细权限 | 10 类 hook 事件确定性拦截/批准；allow/deny/ask；系统级沙箱 | 硬编码 write 确认 + 硬编码沙箱 | 安全策略不可配置、不可扩展 | **中** |
| 9 | Checkpoints / 回退 | 会话快照、rewind/undo | 无（依赖外部 git，而 git 未集成） | 错误操作无法快速撤销 | **中** |
| 10 | Skills | 按需加载的能力包（SKILL.md + 脚本 + 资源） | 无 | 无法封装可复用领域工作流 | **中低** |
| 11 | 体验 / 多端 / 多模型 / Artifacts | CLI/IDE/Web/Desktop/移动端；多模型路由；Artifacts | 单一 Electron 桌面 + 单一 Deepseek + 基础 chat UI | 覆盖面与体验差距（非本质） | **低** |

## 三、按用户价值的扩展路线图

严格按用户价值从高到低。每阶段给出**为什么值这个位次**与**验收标准**，并保持"教学优先、最小、模块化"原则。

### 阶段 1 —— 终端执行 + 结果反馈闭环（用户价值第 1）

从"文件助手"到"coding agent"的质变。

- **做什么**：新增 `run_command` 工具——在 workspace 内执行、超时、输出长度截断、禁止交互式命令、危险命令（`rm -rf`、`git push --force` 等）走审批。
- **为什么**：没有执行，后面的测试/构建/git/装依赖都无从谈起，agent 永远无法自校验。
- **安全（不可省）**：这是最大攻击面，必须加超时、输出截断、危险命令审批；把命令执行边界纳入已有 deterministic 沙箱层，不让模型"自觉"安全。
- **教学价值**：ReAct 闭环"真正闭环"的一步——agent 第一次能根据运行结果修正自己。
- **验收**：agent 能运行 `pnpm test`、看到失败、并据此修复后通过。

### 阶段 2 —— 精确编辑 + Diff 审查 + Git 安全集成（用户价值 2/3）

- **做什么**：新增 `edit_file`（精确字符串替换，等价于 `Edit`），保留 `write_file` 做整体覆盖；工具返回/UI 展示 unified diff、逐处确认；git 默认切分支、按需 commit、diff 视图、可回退。
- **为什么**：精确编辑 + diff 让 agent 在真实代码库"能用"，git 让改动"可审查、可回退"。
- **验收**：agent 对真实仓库做多文件小改动并展示 diff，用户审阅后一键提交/回退。

### 阶段 3 —— 上下文与记忆（用户价值 4）

- **做什么**：读 workspace 根 `CLAUDE.md`/`AGENTS.md` 注入 system prompt；长期记忆（跨会话）；上下文管理（token 预算收紧 + 历史压缩/摘要）；prompt caching（取决于 provider）。
- **为什么**：没有它，长任务/多文件场景会失忆退化，前面能力无法可靠发挥。
- **验收**：约定写在项目指令里，重启后 agent 仍遵守；长会话自动压缩且不丢关键信息。

### 阶段 4 —— 规划模式（用户价值 5）

- **做什么**：只读探索 → 产出方案 → 用户批准 → 才进入执行（与现有 write-approval 呼应，但提前到"动手前"）。
- **为什么**：复杂任务先对齐再动手，省 token、更正确、更可信。
- **验收**：复杂任务先出方案，批准后才改文件。

### 阶段 5 —— 工具面扩展 + MCP（用户价值 6）

- **做什么**：内置 `WebFetch`/`WebSearch`；实现 MCP client（stdio 起手），接入外部工具服务器。
- **为什么**：扩大"能做什么"边界，进入工具生态。
- **验收**：agent 能查最新依赖文档；能连一个 MCP server（如 GitHub）。

### 阶段 6 —— 子代理 / 并行（用户价值 7）

- **做什么**：子代理（独立上下文、只回传摘要）、简单并行扇出、后台长任务。
- **为什么**：大任务并行、保护主上下文。
- **验收**：大范围搜索/评审由子代理完成，主上下文不被细节污染。

### 阶段 7 —— 安全/体验加固（用户价值 8–11 收尾）

- **做什么**：Hooks（PreToolUse 等）、可配置权限规则、checkpoints/undo、注入防御强化；再往后 Skills、Artifacts、IDE 集成、多模型路由。
- **为什么**：底线已有，这些是"从能用变可靠/可配置/好用"的收尾。
- **验收**：按需批准策略可配置；错误可一键回退。

## 四、不能忽略的横向因素：模型能力

上述差距都可以"加功能"补上，但**每一项的天花板都由底层模型决定**。Claude Code 的强工具调用、长上下文、指令遵循、planning 能力建立在 Claude Opus/Sonnet 这一档模型之上；Deepseek 能用，但天花板不同。

当前 `LLMAdapter` 抽象 + `AgentConfig.model` 已留好切换点。建议把**"模型可替换/多模型路由"当成贯穿始终的暗线**，而非单独阶段——扩展功能的同时可随时换更强模型来放大效果。这对教学项目尤其有价值：学生能直观看到"同一 agent、换个模型"的行为差异。

## 五、下一步建议

- **只做阶段 1（终端执行）**。它是唯一"从 0 到 1"的差距，做完它 MVP 才第一次有资格被叫做 coding agent；其余都是"从 1 到 N"。
- 阶段 1 落地时，把 `ToolSandbox` 思路平移过来：命令执行同样走 deterministic 边界（超时、输出截断、危险命令审批）。
- 阶段 2 的 `edit_file` + diff 是紧随其后的第二优先，直接决定 agent 在真实代码库是否"能用"。
